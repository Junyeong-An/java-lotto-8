# java-lotto-precourse

---
## 구현할 기능 목록
### 입력(Input)

- [x] 로또 구입 금액 입력

* 1,000원 단위로 입력받는다.

* 1,000원으로 나누어 떨어지지 않으면 예외 발생 ([ERROR] 구입 금액은 1000원 단위여야 합니다.).

* 숫자가 아닌 값 입력 시 예외 발생 ([ERROR] 금액은 숫자만 입력 가능합니다.).

- [x] 당첨 번호 입력

* 쉼표(,)로 구분된 6개의 숫자 입력.

* 1~45 범위를 벗어나면 예외 발생.

* 중복된 숫자가 있으면 예외 발생.

* 개수가 6개가 아니면 예외 발생.

* 실패 시 해당 입력부터 재시도.

- [x] 보너스 번호 입력

* 1~45 범위의 정수, 당첨 번호와 중복 불가.

* 실패 시 해당 입력부터 재시도.

### 로또 발행 (Lotto Issue)

- [x] 구입 금액에 따라 로또 개수 계산 (금액 / 1000)

- [x] Randoms.pickUniqueNumbersInRange(1, 45, 6)를 사용해 중복되지 않은 6개 번호 생성

- [x] 각 로또 번호를 오름차순 정렬 후 저장

- [x] 발행 직후 "%d개를 구매했습니다." 출력

- [x] 생성된 모든 로또 번호를 한 줄에 하나씩 출력
```
2개를 구매했습니다.
[8, 21, 23, 41, 42, 43]
[3, 5, 11, 16, 32, 38]
```

### 당첨 결과 계산 (Winning Result)

- [x] 사용자가 구매한 모든 로또와 당첨 번호 비교

- [x] 일치 개수 계산 및 5개 일치 시 보너스 번호 일치 여부 반영

- [x] 5개 일치 시 보너스 번호 포함 여부 확인

- [x] 등수별 결과 집계
```
등수	조건	상금
1등	6개 일치	2,000,000,000원
2등	5개 + 보너스	30,000,000원
3등	5개 일치	1,500,000원
4등	4개 일치	50,000원
5등	3개 일치	5,000원
```
### 출력(Output)

- [x] 구매한 로또 개수 및 번호 목록 출력

- [x] 당첨 통계 헤더 출력: "당첨 통계", 구분선 "---"
```
당첨 통계
---
3개 일치 (5,000원) - 1개
4개 일치 (50,000원) - 0개
5개 일치 (1,500,000원) - 0개
5개 일치, 보너스 볼 일치 (30,000,000원) - 0개
6개 일치 (2,000,000,000원) - 0개
총 수익률은 62.5%입니다.
```


- [x] 수익률 = (총 당첨금 / 구매 금액) × 100
 * 소수점 둘째 자리에서 반올림 (String.format("%.1f", ratio))

### 예외 처리 (Exception Handling)

- [x] 입력값이 잘못된 경우 IllegalArgumentException 발생

- [x] 예외 메시지는 반드시 [ERROR]로 시작해야 함

- [x] 예외 발생 시 해당 입력부터 다시 진행

## 고민한 점 

### 상수화 전역 처리
프로젝트 전반에 흩어진 숫자/문자 리터럴을 Numbers, Messages로 중앙화했습니다. 상수 파일을 작성하다보니 너무 커지는 것 같아 고민이 되었습니다. 그래서 숫자와 문구를 따로 모았습니다. 숫자는 Numbers, 문구는 Messages에 넣어 가독성 좋게 분리하였습니다
특히 [ERROR] 프리픽스를 상수화해 모든 에러 메시지에 일관되게 적용하고, 통계 라인 포맷("%s - %d개")도 상수로 빼서 출력 형식을 고정했습니다.
한편, 도메인 의미를 갖는 상수는 “해당 도메인에 남겨두는 원칙”을 유지했습니다. 예를 들어 등수/상금/표시 문자열은 enum LottoRank의 필드로 보관하여 enum과 메시지의 결합을 낮추고, 도메인 내부 규칙을 외부 메시지에 의존하지 않도록 했습니다.

### 입력 재시도·예외 처리 정책 일관화
요구사항의 “잘못된 입력 시 해당 단계부터 재시도”와 UI 로직 테스트 제외 원칙을 지키기 위해, 재시도 루프는 controller에서만 처리하고 domain은 검증 실패 시 IllegalArgumentException만 던지도록 분리했습니다. 
숫자 파싱 오류(NumberFormatException)와 도메인 검증 오류(IllegalArgumentException)를 구분해 잡고, 메시지는 Messages 상수를 사용해 [ERROR] 접두와 문구를 일관되게 출력합니다.
입력 흐름은 금액 → 발행/출력 → 당첨 번호 → 보너스 번호 순으로 고정하고, 각 단계는 독립 루프를 통해 실패 시 이전 단계로 되돌아가지 않도록 했습니다.
